# 02 抓包结果 · 学习通接口清单（2026-09-21，真实登录态，账号「张小明」）

> 采集方式：受管浏览器（Edge/Playwright, CDP）+ 人工走真实流程；证据见 `20-captures/`。
> 本文件只记录**已实测**的东西；未确认的写在「未决」。

## TL;DR
1. 登录态足够，**接口可脱离页面重放**：视频进度上报那条 GET，原样重发 → 200，响应 `{"isPassed":false,...}`。
2. 视频刷课的本质：**周期性 GET `mooc-ans/multimedia/log/a/{userid}/{hash}`**，攒够 `playingTime` 后响应里 `isPassed` 变 `true`。
3. 关键难点不是登录，是 `enc` / `attDurationEnc` / `otherInfo` 里的 `enc_*` 这些**加密参数**是否与 `playingTime`/时间绑定。绑定 → 必须复用页面 JS；不绑定 → 可纯 HTTP 重放。
4. 完成条件（页面原文）：**观看时长 ≥ 总时长 90%**，未完成前**不可倍速、不可拖拽、不可离开/最小化**。

## 四·补 · ⭐ `enc` 算法（已破解并验证，2026-09-21 01:00）

**结论**：`enc` 完全客户端生成，盐值硬编码，**无需服务端密钥**。

```
enc = md5( "[" + clazzId + "][" + userid + "][" + jobid + "][" + objectId
         + "][" + playingTime*1000 + "][" + "d_yHJ!$pdA~5"
         + "][" + duration*1000 + "][" + clipTime + "]" )
```

- `clipTime` 用字符串形式（如 `0_589`）。
- 盐值：`d_yHJ!$pdA~5`（出现在 `ananas/videojs-ext/videojs-ext.min.js`，调用点 `Ext[...][...](...9 参数..., 'd_yHJ!$pdA~5', ...)`）。
- **md5 是标准 MD5**（已用 `md5('abc')` 校验）。

**验证记录**：
| playingTime(ms) | 计算值 | 对照 |
|---|---|---|
| 44000 | `5c759584a2cb851b2b51963de4a93c0f` | 运行时 hook 到的真实输出 ✅ |
| 0 | `3ffc3ac2ee310d17dc37d8c4de177c95` | 抓包里那条真实 `enc=` ✅ |

采集方式：在播放器 iframe 里 hook 全局 `md5`，播放视频触发一次真实上报，记录输入/输出。
证据：`20-captures/enc-md5-capture.json`；复算脚本：`tools/verify_enc.py`。

**⚠️ 注意**：`enc` 包含 `playingTime` ⇒ 每次上报都要重算（但只是纯计算）。
`attDurationEnc` 本次未捕到（推测加载时算，同一视频内为常量）。

## 附录 · 登录二维码的生命周期（2026-09-21 实测）

- 二维码内容（用 `zxing-cpp` 解出，不是猜的）：
  `https://passport2.chaoxing.com/toauthlogin?uuid=<uuid>&enc=<enc>&xxtrefer=&clientid=&type=0&mobiletip=`
- **寿命 ≈ 150 秒**。依据：官方登录页内联 JS `qrInterValObj = window.setInterval(loopStatus, 3000)`，
  `success` 回调里 `if (c >= 50) { clearInterval(qrInterValObj); $(".ewmDisable").show(); }` —— 3s × 50 = 150s
  之后页面显示「二维码已失效 / 重新获取」。
- **服务端不会主动说"过期"**：连续 199 次 `POST /getauthstatus/v2` 全部返回
  `{"mes":"未登录","type":"3","status":false}`（HTTP 200），关键字「过期/失效」一次都没出现。
  ⇒ 过期必须由客户端自己计时（照抄官方 50 次计数），不能等服务端发话。
- 刷新 = `POST /refreshQRCode` → 返回**新的** `uuid` + `enc` → 再 `GET /createqr?uuid=<新uuid>&fid=-1`。
  实测刷新后得到的是另一张可正常解码的新码（uuid 确实变了）。
- 官方页那个「重新获取」按钮其实执行的是 `window.location.reload()`（整页重来）。
- 复现脚本：`tools/probe_qr_ttl.py`、`tools/probe_qr_ttl_long.py`、`tools/probe_qr_payload.py`、
  `tools/probe_status_keywords.py`、`tools/probe_login_page_js.py`、`tools/probe_refresh_deep.py`。
